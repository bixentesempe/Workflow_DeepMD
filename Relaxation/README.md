# Surface relaxation pipeline — build → VASP relax → back to LAMMPS

*[English version below](#english) — [Version française plus bas](#francais)*

<a name="english"></a>
## English

### What this is

Three standalone scripts that prepare a relaxed W(110)/W(100) surface
(pure or with adsorbed O "impurities") for [`Lammps_dynamic`](../Lammps_dynamic/):
build the lattice, relax it with VASP, convert the relaxed structure back
to a LAMMPS data file. They are not called automatically by anything —
you run each step by hand, in order.

```
buildLAMMPSPOSCAR.py          lammps2poscar.py         run_relaxation.slurm       contcar2LaampsDatafile.py
  (build BCC lattice)  --->  (LAMMPS -> VASP POSCAR)  ---> (VASP relaxation) --->   (CONTCAR -> LAMMPS)
  LAMMPS_POSCAR                    POSCAR              CONTCAR (+ OUTCAR)        LAMMPS_POSCAR_relaxed
                                                                                          |
                                                                                          v
                                                                     used by ../Lammps_dynamic/massif_lammps.sh
```

### Step 1 — `buildLAMMPSPOSCAR.py`: build the lattice

Generates a BCC slab (W by default) as a LAMMPS data file: surface (110)
or (100), any lattice parameter, `nx * ny` supercell, `nlayers` layers,
vacuum on top for H2, optional adsorbed O atoms at explicit Cartesian
positions (`--add-O x,y,z`, repeatable — this is the "impure" lattice).
Atom IDs 1 and 2 are reserved for H1/H2 (added later by the
`Lammps_dynamic` generators) — W/O atoms start at ID 3.

```bash
./buildLAMMPSPOSCAR.py -a 3.2398 --surface 110 --nx 2 --ny 2 --nlayers 5 \
    --vacuum 15 -o LAMMPS_POSCAR
```

**Freezing atoms is opt-in, and off by default** (most relaxations are
full, unconstrained relaxations): pass `--freeze-bottom N` (freeze the N
bottom layers) and/or `--freeze-z-below ZMAX` if you actually want some
atoms fixed. Frozen atoms get a `# fixed` comment in the data file —
steps 2 and 4 below pick this up automatically, so you only ever decide
this once, here.

### Step 2 — `lammps2poscar.py`: convert to a VASP POSCAR

```bash
./lammps2poscar.py LAMMPS_POSCAR POSCAR
```

Reads the LAMMPS data file with ASE, drops the H species (nothing to
relax there, it's the projectile placeholder — `--drop` to change),
orders species to match your POTCAR (`--order`, default `W,O`), and
writes a `POSCAR` with `Selective dynamics`.

Freezing: **defaults to nothing frozen**. If step 1 marked atoms with
`# fixed`, those are reused automatically. Override with `--fix-z Z`
(explicit altitude), `--fix-center` (auto-detect the central W layer —
opt-in fallback, not a silent default), or force `--no-fix`.

You still need to bring your own `INCAR`, `KPOINTS`, `POTCAR` (and
`vdw_kernel.bindat` if using a vdW-DF functional) — these aren't
generated by any script here.

### Step 3 — `run_relaxation.slurm`: relax with VASP

```bash
sbatch run_relaxation.slurm
```

Runs `vasp_std` (adjust `module load vasp/...` and the `#SBATCH`
resources to your cluster) and checks `OUTCAR` for ionic convergence at
the end. Produces `CONTCAR`. If you need to resume after a walltime cut,
uncomment the `cp CONTCAR POSCAR` line noted in the script — never do
that on a first run.

### Step 4 — `contcar2LaampsDatafile.py`: back to LAMMPS

```bash
./contcar2LaampsDatafile.py CONTCAR LAMMPS_POSCAR_relaxed
```

Converts the relaxed `CONTCAR` back to the same LAMMPS data format as
step 1 (same ID/ordering convention), ready to hand to
[`../Lammps_dynamic/massif_lammps.sh`](../Lammps_dynamic/README.md).
Handles triclinic cells correctly (rotates cell **and** positions
coherently into LAMMPS' lower-triangular convention via ASE's `Prism`).

Freezing: **defaults to nothing frozen**, unless the `CONTCAR` itself
carries a `Selective dynamics` constraint (VASP echoes back whatever you
set in step 2, so this just closes the loop automatically). Same
`--fix-z` / `--fix-center` / `--no-fix` overrides as step 2.

### Requirements

- Python 3 with `numpy` and `ase` (Atomic Simulation Environment) — used
  by `lammps2poscar.py` and `contcar2LaampsDatafile.py` for robust
  LAMMPS/VASP I/O and triclinic-cell handling.
- A working VASP installation reachable from `run_relaxation.slurm`
  (module name is cluster-specific, adjust it).
- SLURM (`sbatch`).

### Notes / pitfalls this README exists to spare you

- **LAMMPS_POSCAR header count.** `buildLAMMPSPOSCAR.py` used to declare
  `n_surface + 2` atoms in the header (anticipating H1/H2 added later by
  `Lammps_dynamic`) while only writing `n_surface` atom lines. That's
  fine for the `Lammps_dynamic` generators (they recompute the header
  anyway) but made `lammps2poscar.py`'s strict ASE reader crash
  (`StopIteration`, end of file reached before the declared atom count).
  Fixed: the header now always matches what's actually written.
- **Consistent freezing across steps.** Earlier, `lammps2poscar.py` and
  `contcar2LaampsDatafile.py` each independently *guessed* a "central
  layer" to freeze if you didn't pass `--fix-z` — silently ignoring
  whatever `--freeze-bottom` choice you made in step 1, and freezing a
  *different* set of atoms with (confusingly) the same count. Fixed: the
  `# fixed` tags / `Selective dynamics` constraint set in step 1 now
  propagate automatically through steps 2 and 4; the central-layer guess
  is only used if you explicitly ask for it with `--fix-center`.
- **Nothing frozen by default.** Since most relaxations here are meant to
  be fully unconstrained, none of the four scripts freezes anything
  unless you explicitly ask (`--freeze-bottom`/`--freeze-z-below` in step
  1, or `--fix-z`/`--fix-center` later).
- **`run_relaxation.slurm` log paths.** `-o`/`-e` used to point at
  `logs/relax_%j.out`, but `sbatch` does not create missing output
  directories — the submission would fail outright if `logs/` didn't
  already exist. Fixed: logs now write next to the script.

## Français

### Qu'est-ce que c'est

Trois scripts autonomes qui préparent une surface W(110)/W(100) relaxée
(pure ou avec des "impuretés" O adsorbées) pour
[`Lammps_dynamic`](../Lammps_dynamic/) : construire la maille, la relaxer
avec VASP, reconvertir la structure relaxée en data file LAMMPS. Rien
n'appelle ces scripts automatiquement — tu lances chaque étape à la main,
dans l'ordre.

```
buildLAMMPSPOSCAR.py          lammps2poscar.py         run_relaxation.slurm       contcar2LaampsDatafile.py
 (construit la maille BCC) -> (LAMMPS -> POSCAR VASP) -> (relaxation VASP)  ->     (CONTCAR -> LAMMPS)
  LAMMPS_POSCAR                    POSCAR              CONTCAR (+ OUTCAR)        LAMMPS_POSCAR_relaxed
                                                                                          |
                                                                                          v
                                                              utilise par ../Lammps_dynamic/massif_lammps.sh
```

### Étape 1 — `buildLAMMPSPOSCAR.py` : construire la maille

Génère une dalle BCC (W par défaut) en data file LAMMPS : surface (110)
ou (100), paramètre de maille au choix, supercellule `nx * ny`,
`nlayers` couches, vide au-dessus pour H2, ajout optionnel d'atomes O
adsorbés à des positions cartésiennes explicites (`--add-O x,y,z`,
répétable — c'est la maille "impure"). Les IDs 1 et 2 restent réservés
pour H1/H2 (ajoutés plus tard par les générateurs de `Lammps_dynamic`) —
les atomes W/O commencent à l'ID 3.

```bash
./buildLAMMPSPOSCAR.py -a 3.2398 --surface 110 --nx 2 --ny 2 --nlayers 5 \
    --vacuum 15 -o LAMMPS_POSCAR
```

**Figer des atomes est optionnel, et désactivé par défaut** (la plupart
des relaxations sont complètes, sans contrainte) : passe
`--freeze-bottom N` (fige les N couches du bas) et/ou
`--freeze-z-below ZMAX` si tu veux vraiment figer certains atomes. Les
atomes figés reçoivent un commentaire `# fixed` dans le data file — les
étapes 2 et 4 ci-dessous le reprennent automatiquement, donc tu ne
décides ça qu'une seule fois, ici.

### Étape 2 — `lammps2poscar.py` : conversion en POSCAR VASP

```bash
./lammps2poscar.py LAMMPS_POSCAR POSCAR
```

Lit le data file LAMMPS via ASE, retire l'espèce H (rien à relaxer là,
c'est juste le placeholder du projectile — `--drop` pour changer),
ordonne les espèces selon ton POTCAR (`--order`, défaut `W,O`), et écrit
un `POSCAR` avec `Selective dynamics`.

Figeage : **rien de figé par défaut**. Si l'étape 1 a marqué des atomes
avec `# fixed`, ils sont repris automatiquement. Surcharge possible avec
`--fix-z Z` (altitude explicite), `--fix-center` (détection auto de la
couche W centrale — repli optionnel, pas un défaut silencieux), ou force
`--no-fix`.

Il te faut quand même fournir toi-même `INCAR`, `KPOINTS`, `POTCAR` (et
`vdw_kernel.bindat` si tu utilises une fonctionnelle vdW-DF) — rien ici
ne les génère.

### Étape 3 — `run_relaxation.slurm` : relaxation VASP

```bash
sbatch run_relaxation.slurm
```

Lance `vasp_std` (adapte `module load vasp/...` et les ressources
`#SBATCH` à ton cluster) et vérifie la convergence ionique dans `OUTCAR`
à la fin. Produit un `CONTCAR`. Pour reprendre après une coupure de
walltime, décommente la ligne `cp CONTCAR POSCAR` notée dans le script —
jamais au premier run.

### Étape 4 — `contcar2LaampsDatafile.py` : retour vers LAMMPS

```bash
./contcar2LaampsDatafile.py CONTCAR LAMMPS_POSCAR_relaxed
```

Reconvertit le `CONTCAR` relaxé dans le même format LAMMPS que l'étape 1
(même convention d'IDs/ordre), prêt à être donné à
[`../Lammps_dynamic/massif_lammps.sh`](../Lammps_dynamic/README.md).
Gère correctement les cellules tricliniques (tourne cellule **et**
positions de façon cohérente vers la convention lower-triangular de
LAMMPS, via `Prism` d'ASE).

Figeage : **rien de figé par défaut**, sauf si le `CONTCAR` lui-même
porte une contrainte `Selective dynamics` (VASP recopie fidèlement ce que
tu as réglé à l'étape 2, donc la boucle se referme automatiquement).
Mêmes surcharges `--fix-z` / `--fix-center` / `--no-fix` qu'à l'étape 2.

### Prérequis

- Python 3 avec `numpy` et `ase` (Atomic Simulation Environment) —
  utilisé par `lammps2poscar.py` et `contcar2LaampsDatafile.py` pour une
  lecture/écriture LAMMPS/VASP robuste et la gestion des cellules
  tricliniques.
- Une installation VASP fonctionnelle, accessible depuis
  `run_relaxation.slurm` (le nom du module est spécifique au cluster,
  à adapter).
- SLURM (`sbatch`).

### Notes / pièges que ce README t'évite

- **Comptage d'atomes dans le header du LAMMPS_POSCAR.**
  `buildLAMMPSPOSCAR.py` déclarait `n_surface + 2` atomes dans le header
  (anticipant l'ajout ultérieur de H1/H2 par `Lammps_dynamic`) tout en
  n'écrivant que `n_surface` lignes. Ça passait pour les générateurs de
  `Lammps_dynamic` (qui recalculent le header de toute façon), mais ça
  faisait planter le lecteur ASE strict de `lammps2poscar.py`
  (`StopIteration`, fin de fichier atteinte avant le compte annoncé).
  Corrigé : le header correspond maintenant toujours à ce qui est
  réellement écrit.
- **Cohérence du figeage entre les étapes.** Avant, `lammps2poscar.py` et
  `contcar2LaampsDatafile.py` *devinaient* chacun de leur côté une
  "couche centrale" à figer si `--fix-z` n'était pas fourni — ignorant
  silencieusement le choix `--freeze-bottom` fait à l'étape 1, et figeant
  un ensemble d'atomes *différent* avec (de façon trompeuse) le même
  nombre. Corrigé : les tags `# fixed` / la contrainte `Selective
  dynamics` posés à l'étape 1 se propagent maintenant automatiquement à
  travers les étapes 2 et 4 ; la devinette "couche centrale" n'est
  utilisée que si tu la demandes explicitement avec `--fix-center`.
- **Rien de figé par défaut.** Puisque la plupart des relaxations ici
  sont censées être totalement libres, aucun des quatre scripts ne fige
  quoi que ce soit sans demande explicite (`--freeze-bottom`/
  `--freeze-z-below` à l'étape 1, ou `--fix-z`/`--fix-center` ensuite).
- **Chemins de logs de `run_relaxation.slurm`.** `-o`/`-e` pointaient
  vers `logs/relax_%j.out`, mais `sbatch` ne crée pas les dossiers de
  sortie manquants — la soumission échouait directement si `logs/`
  n'existait pas déjà. Corrigé : les logs s'écrivent maintenant à côté du
  script.
